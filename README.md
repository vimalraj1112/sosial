# SOSIAL — website

A premium marketing site for **SOSIAL**, a marketing and creative brand in Bengaluru. The build brings digital marketing, branding, websites and visual production together under two divisions:

- **Digital Marketing & Creative Growth**
- **Video Production & Photography**

Built with the Next.js App Router, TypeScript, Tailwind CSS v4, Motion and Lenis.

> **Build status:** every navigation and footer route now resolves. The portfolio, team profiles and testimonials remain clearly labelled placeholders until approved client material is supplied. See `CLIENT_ASSETS.md` for the open items.

---

## Stack

| Layer      | Choice                                          |
| ---------- | ----------------------------------------------- |
| Framework  | Next.js 16 (App Router, Turbopack)              |
| Language   | TypeScript                                      |
| Styling    | Tailwind CSS v4 + brand tokens                  |
| Motion     | Motion (React) with reduced-motion paths        |
| Scrolling  | Lenis, medium-paced; disabled for reduced motion |
| Forms      | React Hook Form + Zod                           |
| Icons      | Lucide + original inline glyphs                 |
| Fonts      | Plus Jakarta Sans, Inter + Playfair Display via `next/font` |

Server components are the default. Client components are limited to navigation, the splash intro, forms and interactive media.

## Editing content

- **Contact details, nav, announcement, intro timings, social profiles:** `src/data/brand.ts`
- **Services and service FAQs:** `src/data/services.ts`
- **Concept projects:** `src/data/work.ts` — every entry is an **illustrative concept** and must stay labelled until a real client approves the work.
- **Testimonials:** `src/data/testimonials.ts` — sample copy only. Do not attribute to a real person or company without written approval.
- **Insights:** `src/data/insights.ts` — six editorial articles with structured content blocks.
- **Media:** `src/data/media.ts`; drop replacements into `public/assets/`.

### The honesty rules built into the site

- No invented client logos, ratings, awards, press or endorsements.
- “Platforms we work in” lists platforms by name only; it is not a client-logo strip.
- Concept work carries a visible **Illustrative concept · no verified results** label and a longer disclaimer.
- Testimonials are marked as sample layouts, not client quotes. The testimonial page is `noindex` until approved quotes replace the samples.
- Team cards show disciplines and **Profile pending**; no names or portraits have been invented.
- Social icons are muted and non-interactive until real profile URLs are supplied. Instagram is live.
- No fixed fees, response-time guarantees or performance guarantees are published. Scope, deliverables, timeline and fees are agreed in writing.
- The enquiry form only reports success after a delivery channel accepted the message.

## Enquiry delivery

`POST /api/enquiry` validates with Zod, rate-limits (5 per 10 minutes per IP, in-memory), rejects honeypot and sub-1.5s submissions, and de-duplicates retries by idempotency key.

Delivery order:

1. **Resend** if `RESEND_API_KEY`, `ENQUIRY_TO_EMAIL` and `ENQUIRY_FROM_EMAIL` are set.
2. **Gmail/SMTP** if `SMTP_USER` and `SMTP_PASS` are set. Gmail defaults to `smtp.gmail.com:465`; other SMTP hosts can be set with `SMTP_HOST`, `SMTP_PORT` and `SMTP_SECURE`.
3. **Webhook** if `ENQUIRY_WEBHOOK_URL` is set (JSON POST).
4. **Local file sink** in development, or in production only when `ENQUIRY_FILE_SINK=on` — writes to `.data/enquiries/`.
5. Otherwise **503** with a message telling the visitor to email directly.

### Gmail SMTP setup

1. Turn on 2-Step Verification for `sosial.solutions@gmail.com`.
2. Create a Google **App password** (Google Account → Security → App passwords).
3. Copy `.env.example` to `.env.local`, set `SMTP_USER=sosial.solutions@gmail.com`, and paste the app password into `SMTP_PASS`. Spaces in the app password are fine.
4. Keep `ENQUIRY_TO_EMAIL` and `ENQUIRY_FROM_EMAIL` pointed at the same mailbox, then restart the app.

The app password is a secret. `.env.local` is ignored by Git; add the same variables in the hosting provider's environment settings for production. If Gmail blocks server delivery, switch to Resend or a webhook. Serverless filesystems are ephemeral, so the file sink is for local preview only. The in-memory rate limiter is per instance; move it to Redis or the form provider for multi-region traffic. The idempotency key is recorded only after a delivery channel succeeds, so a retry after a failure is allowed through.

## Splash intro

- Plays on every full page load or refresh, on any route. Client-side navigation does not replay it.
- Uses the supplied SOSIAL lockup from the PDF; no temporary orbit mark remains in the live UI.
- Skippable by click, `Escape`, `Enter`, `Space`, or the visible **Skip intro** button.
- Auto-exits at ~2.3s (hard fallback at 4.2s even if animation fails).
- Honours `prefers-reduced-motion`: final composition immediately, no stagger.
- Locks scroll and makes `#site-content` inert while visible; never blocks SSR, SEO or direct navigation.
- Replayable from the footer on any page via a custom event.
- `?intro=0` is a test/preview bypass; it is removed from the URL after load. Normal refreshes still play.
- Disable globally with `intro.enabled = false` in `src/data/brand.ts`.

## Scrolling and motion

- `SmoothScroll` runs Lenis with a medium `lerp` (0.1). It is deliberately quieter than the splash animation.
- Touch scrolling stays native; wheel and keyboard scrolling use Lenis.
- `prefers-reduced-motion` disables Lenis, scroll-triggered reveals and the splash stagger.
- The splash and mobile menu dispatch `sosial:scroll-lock` so Lenis stops while either surface is open.
- Project imagery moves at a slow, bounded parallax (`ParallaxMedia`) and settles still for reduced-motion users.
- Every page opens with the shared `HeroBackdrop`: an `ArrowField` canvas that points toward the cursor and drifts on its own when idle, with the same contrast gradients used on the homepage. It pauses off-screen and becomes a static composition for reduced-motion users. Legal pages use the backdrop for a compact opening hero, then continue on the light reading surface.

## Accessibility

- Skip link to `#main-content`; landmarks and heading order on every page.
- Focus styles on all interactive elements; the intro moves focus to the skip control.
- Accordions and the mobile menu are keyboard operable with `aria-expanded` / `aria-controls`.
- Decorative artwork is `aria-hidden`; meaningful images have alt text.
- Reduced-motion users get static final states (no scroll-triggered movement).
- Mobile menu scrolls at short viewport heights so its CTA remains reachable.

## Deployment

1. Push the repository to your host (Vercel is the simplest fit for Next.js).
2. Add the environment variables from `.env.example`.
3. Set `NEXT_PUBLIC_SITE_URL` to the live origin.
4. Build command `npm run build`, output handled by the platform.
5. After launch, submit `/sitemap.xml` and verify the enquiry inbox end to end.

The site currently has no database. If enquiries must be stored, use the webhook channel or add a database adapter in `src/app/api/enquiry/route.ts`.
